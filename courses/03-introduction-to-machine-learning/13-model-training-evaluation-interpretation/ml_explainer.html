01

Overfitting vs Underfitting

Every model tries to draw a line through the data. Too lazy and it misses the shape. Too eager and it traces every wobble — including the noise. The sweet spot is in between.

Underfitting

The model is too simple to capture the real pattern. It's wrong even on data it has already seen.

Everyday version: studying only the chapter titles before an exam — you miss the actual content.

Overfitting

The model memorizes the training data — noise and all — so it looks perfect in practice but fails on anything new.

Everyday version: memorizing last year's exact exam answers, then freezing when the questions change.

02

High Bias vs High Variance

These are the two reasons a model goes wrong — the deeper cause behind underfitting and overfitting. Think of a model taking the same test many times, each time trained on a slightly different sample of data. Where do the shots land?

High bias

The model makes strong, simple assumptions and sticks to them. It's consistently off — in the same direction — no matter the data. This causes underfitting.

On target? Tightly grouped, but far from the bullseye.

High variance

The model reacts to every little change in the training data. Retrain it on a new sample and it gives a very different answer. This causes overfitting.

On target? Scattered everywhere — sometimes near, sometimes wild.

03

Interpretable by Design vs Needs SHAP

Some models you can just read — the logic is right there. Others are so tangled inside that you need a separate tool, like SHAP, to ask "why did you decide that?" after the fact.

Interpretable by design

You can trace the decision directly. The model is its own explanation — weights, a short rule, a shallow tree.

Like: a printed recipe. Every step is visible.

Needs SHAP (model-agnostic)

Too many moving parts to read directly. SHAP probes the model from outside and reports how much each feature pushed the prediction.

Like: a dish from a secret kitchen — you taste-test to reverse-engineer what's in it.

Real example — a loan decision
Interpretable: "Declined because income < $30k" — you read the rule straight off. Needs SHAP: a 500-tree model declines the loan; SHAP then shows income pushed it −40%, credit history +15%, so you can finally explain it to the customer (and check it's fair).
Why this matters beyond the classroom
Trust
In healthcare, lending, and law, "the model said so" isn't enough — you must show why.
Fairness
SHAP can reveal a model leaning on features it shouldn't, like a proxy for gender or race.
Debugging
If a feature dominates every prediction, that's often a data leak — SHAP surfaces it.
04

Parameters vs Hyperparameters

One quick, clean distinction. Is the value learned by the model as it trains — or is it a knob you set yourself before training even starts?

Parameters

Learned by the model, automatically, during training. You never set these by hand — the data shapes them.

Examples: weights w, bias b, every weight inside a neural network.

Hyperparameters

Set by you before training begins. They control how the model learns, not what it concludes.

Examples: learning rate, number of epochs, tree depth, number of trees.
